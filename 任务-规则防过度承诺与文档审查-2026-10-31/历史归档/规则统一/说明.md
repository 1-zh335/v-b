## 二、为什么用「项目根 AGENTS.md」而不是硬链接/副本

1. **Trae 3.4.7 原生支持**：设置项 `AI.rules.importAgentsMd`（"Include AGENTS.md in context."，默认 `true`，本机未关闭）会把项目根 `AGENTS.md` 纳入规则上下文；`.trae/rules/*.md` 也会被同时加载，故旧项目规则必须删除，否则同一规则注入两遍。
2. **DSH 0.1.1-rc.2 原生支持**：`dsh-agent-instructions` 加载 `$DSH_HOME/AGENTS.md` + 项目根（含 `.git` 的目录）到 cwd 链上的 `AGENTS.md`；已实测发现结果恰为 `["~/.dsh/AGENTS.md", "AGENTS.md"]`。
3. **硬链接/符号链接不可行（实测）**：符号链接创建需管理员权限（本机标准用户，`New-Item -ItemType SymbolicLink` 报"此操作需要管理员权限"）；硬链接虽可建，但 **DSH 的写工具写文件会替换 inode，直接断链**（实测：写 B 后 A 不再同步、`fsutil hardlink list` 只剩一个链接）。用链接会出现"改一处、另一处静默变旧"的问题，故放弃。

## 六、日常维护与注意事项

1. **改规则 = 只改** `v b\AGENTS.md`（Trae / DSH 都会自动生效，无需重启；DSH 已在本会话实测热更新）。
2. 不要恢复 `.trae\rules\工程规范.md`，也不要在 `~/.dsh/AGENTS.md`、Trae 个人规则里写正文——那样会重新产生"同一规则两份"的问题。
3. **Trae 侧注意**：Trae「个人规则」（Rules → 个人规则）里现在是指针；若 Trae 账号云端同步把它覆盖回旧版，请在 Trae UI 里把个人规则改为指针内容（或删除该条个人规则）。Trae 设置里请保持「将 AGENTS.md 包含在上下文中」开关**开启**（默认开启）。
4. **跨工作区**：本文件只在 `v b` 工作区自动生效；其他工作区的 DSH/Trae 会先看到全局指针，需读取本文件；如要其他工作区也自动生效，可在其根目录放一份 `AGENTS.md`（以本文件为准）。
5. 回滚：把 `规则统一\备份\` 中对应文件复制回原路径即可（Trae 项目规则需先 `New-Item -ItemType Directory .trae\rules`）。
6. 本次改动尚未 git 提交；`git status` 会显示：新增 `AGENTS.md`、`规则统一/`，删除 `.trae/rules/工程规范.md`，修改 `README.md`。提交建议：`git add -A && git commit -m "规范：Trae 与 DSH 统一为项目根 AGENTS.md 单一规则文档"`
