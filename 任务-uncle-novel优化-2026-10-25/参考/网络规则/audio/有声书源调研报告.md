## 2. 实测方法

模拟 app 的有声流程（与 `SearchAudioView.withAudioUrl` / `AudioBookShelfView.loadChapter` 一致）：

1. `NovelMatcher.search(1, keyword, rule, …)` → 有声书列表；
2. `NovelSpider.toc(novel.url)` → 章节（曲目）列表；
3. `NovelSpider.content(chapter.url)` → 音频地址（app 即以此地址交给 JavaFX MediaPlayer）；
4. 对音频地址发真实 HTTP GET（带 `Referer=章节页`，跟随 302），记录：状态码、`Content-Type`、字节数、首 4 字节（判断是否 MP3/M4A 帧头）。

- 测试关键词：`斗破苍穹`（有声书资源充足）；
- 判定“可用”的标准：**搜索 → 目录 → 音频 URL 均为 200，且 Content-Type 为 `audio/*`、首字节为有效音频帧头**；
- 工具：`工具\net-rules\AudioTest.java`（应用同款 `novel-analyzer.jar`），原始结果见 `测试数据\18条社区有声规则实测.json` / `.txt`。

## 4. 关键站点的额外探测（为什么“搜到也放不了”）

### 4.1 喜马拉雅（search 可用，曲目/播放地址需签名）

| 请求 | 结果 | 说明 |
| --- | --- | --- |
| `http://search.ximalaya.com/speed/album/v1/list?...kw=斗破苍穹...` | 200，20 条专辑 | 搜索接口仍可用 |
| `https://mobile.ximalaya.com/mobile/v1/album?albumId=54572265&pageSize=1000` | 200，`ret=0`，`data.tracks.list` 78 条（含 trackId/title） | **专辑信息+曲目列表可用**（无播放地址字段） |
| `https://mobile.ximalaya.com/mobile/v1/album/track?albumId=…` | 200 `{"msg":"亲，该内容因故已下架","ret":924}` | 曲目列表接口对新申请失效 |
| `https://www.ximalaya.com/revision/album/v1/getTracksList?albumId=…` | 200 `{"ret":407,"msg":"webtk缺失"}` | 网页端接口需 `webtk` 签名 |
| `https://www.ximalaya.com/revision/play/v1/audio?id=…` | 404 | 播放地址接口需登录态/签名 |
| `https://mobile.ximalaya.com/mobile-playpage/track/v3/baseInfo/<trackId>` | 200 `{"ret":-1,"msg":"亲，系统出错啦"}` | 播放地址接口需 `xm-sign` 签名 |

→ 喜马拉雅可以做到“搜索 + 目录”，但**拿不到可播放 URL**，且签名算法（`xm-sign`/`webtk`）无法在 AnalyzerRule 的 script 里稳定实现 → 不可内置。

### 4.2 酷我听书（search 可用，专辑曲目接口下线）

| 请求 | 结果 | 说明 |
| --- | --- | --- |
| `https://tingshu.kuwo.cn/tingshu/api/search/Search?...&wd=斗破苍穹` + **Android UA** | 200，89 张专辑 | 搜索可用；**桌面 UA 会 403「该版本已停止运营」** |
| `…/tingshu/api/data/album/songs?albumId=…`（旧规则接口） | 200 `{"code":404,"msg":"Error"}` | 曲目接口已下线 |
| `…/tingshu/api/v2/album/songs`、`/album/list`、`/data/album/song` 等 4 种候选 | 全部 `code:404` | 无替代路径 |
| `https://m.kuwo.cn/newh5app/api/mobile/v1/album/songs?albumId=…` | 200 `CSRF Token Not Found!` | 新 H5 接口需 CSRF Token |

→ 只能拿到专辑，拿不到曲目/播放地址 → 不可内置。

### 4.3 懒人听书

- 应用 analyzer 搜索到 10 条，但目录请求 404（规则用旧 `replace` 语法拼 URL，未生效，落到 `…/user/79939507/0/9999`）；
- Python 直接访问搜索页返回空 body（站点对非浏览器请求不友好）；曲目/播放接口需登录 token → 不可内置。

### 4.4 社区规则自身的通用问题（影响全部 18 条）

社区规则普遍用旧版 `"replace": "\"regex:([\\s\\S]+)##<url>$1\""` 语法拼 URL。本机 analyzer 版本中该写法**未生效**（与文本书源同因：replace 只按 `正则##替换` 解析、且 JSONPath 场景行为有差异），导致目录 URL 落到错误地址（如 `…/api/v2/search/<id>`）。**即使站点恢复，这 18 条规则也需要逐条重写 URL 拼接为 `script` 形式。**

## 6. 风险与后续建议

### 6.1 给 Lead 的建议

1. **本次不内置任何有声书源**（`rules-有声可用.json` 为 `[]`）。「寻找有声」功能保持无内置源（或引导用户使用本地音频/书架）。
2. **有声需求可先用 TTS 满足**：内置 TTS 实测 8/8 引擎可用（百度度博文 http/https、思必驰 7 音色，均返回有效 MP3，无需鉴权），阅读器朗读可直接用。
3. 若必须内置有声书源，建议作为**独立后续任务**，路线按可行性排序：
   - a) 找**无需签名**的音频 API（如部分小站直链 mp3/m4a），按 `toc.url = 音频直链 + content 留空` 的方式适配（app 对 audio 规则在 content 无效时会直接使用章节链接，已从 `NovelSpider.content` 字节码确认该兜底逻辑）；
   - b) 对需要签名的平台（喜马拉雅/酷我）**不要尝试在规则内破解**（签名算法/CSRF 依赖浏览器环境，且不稳定）；
   - c) 或改用「番茄小说下载版规则 + 本地 TTS」组合（本次已打通番茄正文）。
4. 合规：有声内容版权归平台/作者，不建议内置来源不明的盗版有声站。

### 6.2 风险

- **站点寿命**：18 条社区规则（2022 年）15 条站点已死，有声站比文本盗版站更不稳定；
- **签名/风控**：存活平台全部有签名、CSRF、webtk 等反爬，规则内无法稳定复刻；
- **防盗链**：即使拿到音频 URL，多数 CDN 需要 `Referer`/`Cookie`，app 播放器（JavaFX MediaPlayer）无法自定义请求头，可能播放失败（app 的“音频有效”检测虽带 Referer，但播放器本身不带）；
- **限速/封 IP**：批量下载有声资源易触发风控。
