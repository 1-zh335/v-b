# 番茄小说下载能力攻关报告（task-1）

> 目标：解决番茄小说「能搜不能下」问题（目录 API 200 空 body、正文端点全空）
> 调研日期：2026-10-27　环境：应用自带 JDK11 + `novel-analyzer.jar`（规则级真实 HTTP）+ Python 探针
> 关键词：西游记 / 诡秘剑主 / 十日终焉 / 苍穹榜：斗破苍穹后传
> 交付：`rules-番茄可用.json`（本目录，可直接导入/内置）、本报告、`update_charset.py`（映射表更新工具）

---

## 1. 结论（TL;DR）

| 问题 | 结论 |
| --- | --- |
| 目录接口 | ✅ **已打通**：`https://fanqienovel.com/api/reader/directory/detail?bookId=<book_id>`，无需签名/无 Cookie，UA+Referer 即可，返回完整章节树 |
| 正文接口 | ✅ **已打通（非 API 路线）**：`https://fanqienovel.com/reader/<itemId>` 阅读页 HTML 内嵌 `window.__INITIAL_STATE__`，其中 `reader.chapterData.content` 即正文 HTML |
| 字体反爬 | ✅ **已解决**：正文汉字被替换为 U+E3E8~U+E55B 的 PUA 私用区码位（自定义字体反爬）；用社区映射表在规则 `script` 内逐字还原，**实测残留 PUA=0、还原率 100%** |
| 签名（X-Argus 等） | ❌ 不需要：官方移动端 API（api5 / novel.snssdk.com）继续返回空 body，但网页版 reader 页走的是**未签名 SSR**，无需破解签名 |
| 有下载能力的规则 | ✅ 已产出并实测：`rules-番茄可用.json`（搜索→目录→正文全链路 OK，3 本免费书验证） |
| 限制 | 付费/受限书 reader 页 404，正文不可得；字体映射表需随字体版本更新 |

> 与 Lead 此前结论的差异：不是通过 `api/reader/full` 拿正文，而是 **reader 页 SSR JSON**；正文里的 PUA 密文用**静态字符映射表**即可还原，可在 AnalyzerRule 里纯脚本实现，无需登录、无需浏览器。

## 3. 字体反爬（PUA）及还原方案

### 3.1 现象

reader 页 `reader.chapterData.content` 里的常用汉字被替换为 **PUA 私用区码位**（U+E3E8 ~ U+E55B），例如：

```
<p>\ue418纪辰醒\ue4fa\ue4fc，差\ue4a8\ue42c吓尿。</p>   ← 原文：「当纪辰醒来时，差点被吓尿。」
```

- 页面 CSS 引入自定义字体 `https://lf6-awef.bytetos.com/obj/awesome-font/c/dc027189e0ba4cd.woff2`（`@font-face`），浏览器用该字体把 PUA 码位渲染成正确字形；
- **同一章两次请求密文完全一致**（映射不是逐请求随机，而是固定字体映射表）；
- 桌面/移动 UA 返回的都是 PUA 密文，不是 UA 问题；
- 纯文本抓取（requests / analyzer）得到的都是密文，必须做字符映射还原。

### 3.2 还原方法（已在规则内实现）

采用社区开源项目 [ckenkuo/fanqie-cdp-downloader](https://github.com/ckenkuo/fanqie-cdp-downloader)（MIT）的 `src/charset.json` 字符映射表：

- 映射表结构：2 套 mode（对应两套字体偏移），各 372 / 371 个字符；
- 解密算法（同该项目 `decoder.py`）：
  - mode0：码位区间 `[58344, 58715]`，`bias = code - 58344` → `charset[0][bias]`；
  - mode1：码位区间 `[58345, 58716]`，`bias = code - 58345` → `charset[1][bias]`；
  - 两套都解一遍，取「残留 PUA 更少」的结果；
- 实测（Python 侧，4 章样本）：

| 章节 | 原始字数 | 原始 PUA 数 | 残留 PUA | 还原率 | 抽样 |
| --- | --- | --- | --- | --- | --- |
| 诡秘剑主 第1章 | 2700 | 1343 | **0** | 100% | 「当纪辰醒来时，差点被吓尿。他正躺在一家店铺的门口…」 |
| 诡秘剑主 第2章 | 2121 | 1113 | **0** | 100% | 「“等等！” 纪辰轻喝一声…」 |
| 西游记 第一回 | 7063 | 2951 | **0** | 100% | 「诗曰：混沌未分天地乱，茫茫渺渺无人见…」 |
| 西游记 第二回 | 7149 | 3244 | **0** | 100% | 「话表美猴王得了姓名，怡然踊跃…」 |

- **在 AnalyzerRule 内实现**：把两张映射表（共 743 字符，约 2.5KB）内嵌到 `content.script`，Nashorn 逐字替换；规则 JSON 总大小 11KB，`RuleHelper` 正常加载、`script` 执行正常。

## 4. 交付规则 `rules-番茄可用.json`

结构（完整内容见文件）：

| 节点 | 实现 |
| --- | --- |
| `search` | 沿用社区规则：`https://novel.snssdk.com/api/novel/channel/homepage/search/search/v1/?aid=13&q={{keyword}}`，JSONPath `$.data.ret_data`；`detail.url` script 生成目录 API 地址：`"https://fanqienovel.com/api/reader/directory/detail?bookId=" + result`（result=`$.book_id`） |
| `toc` | 请求目录 API（带 UA/Referer/Accept 头），`list = $.data.chapterListWithVolume[*][*]`（Jayway JSONPath 嵌套数组展开），`name = $.title`，`url = "https://fanqienovel.com/reader/" + $.itemId` |
| `content` | 请求 reader 页 HTML，`script`：① 从 `source` 提取并 `JSON.parse` `window.__INITIAL_STATE__`；② 取 `reader.chapterData.content`；③ `<p>`→换行、去标签、反转义；④ PUA 两套 mode 解码取残留最少者 |
| 其他 | `enabled=true, audio=false, weight=4`；`detail={}`（详情页信息用搜索结果即可） |

> 规则文件由 `工具\net-rules\make_fanqie_rule.py` 生成（字符映射表 + `content_script.js` 模板），改映射只需重跑脚本。
> **site 字段说明（应用内匹配需要）**：规则 site 建议写 **https://fanqienovel.com/**，而搜索请求地址仍写死在 search.params.url（
ovel.snssdk.com/.../search/v1/）。原因：app 在打开/下载书籍时会用**书籍 URL 反查规则**（RuleManager.getOrDefault(url) 按站点匹配），而本规则产出的书 URL 都是 anqienovel.com（目录 API / reader 页），若 site 写搜索域名会导致反查不到规则。Lead 已按此调整并验证通过，ules-可用-v2.json 采用调整后的 site。

## 6. 局限与风险

1. **付费/受限书正文不可得**：reader 页对需要登录/付费的章节返回 404；免费书（西游记、诡秘剑主、十日终焉等）可完整下载。app 端表现：目录正常、部分章节正文获取失败。
2. **字体映射表有版本风险**：当前映射对应字体 `dc027189e0ba4cd`（番茄“awesome-font”）。若番茄更新字体/码位，会出现大量未还原的 PUA 字符。判定与更新：
   - 判定：正文里 U+E3E8~U+E55B 字符占比 > 5%；
   - 更新：运行 `python 工具\net-rules\fanqie\update_charset.py`（从上游仓库拉取最新 `charset.json` 并重新生成规则；脚本已提供）。
3. **反爬/限速**：reader 页逐章请求，实测连续请求正常；仍建议 app 端保持默认单线程/低并发，避免触发风控（未做压力测试，不建议高并发）。
4. **上游依赖**：映射表来自第三方开源项目（MIT），非官方；番茄官方接口随时可能变更（本方案只依赖网页 SSR，风险中等）。
5. **合规**：番茄为付费平台，抓取内容仅供个人学习研究，请勿传播/商用；尊重版权。
