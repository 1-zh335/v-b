# Uncle 小说书源（联网规则）格式说明 & 自建模板

> 适用范围：Uncle小说 5.0.44（增强版）· `conf\rules.json` · novel-analyzer `AnalyzerRule`
> 配套模板：`参考\网络规则\示例-自定义书源模板.json`（字段齐全、URL 占位、可直接导入）
> 实测参考：`参考\网络规则\rules-可用.json`（书趣阁 / 365小说网 / 红袖 / 番茄）

---

## 1. 规则存在哪、什么时候加载、怎么导入

| 事项 | 说明 |
| --- | --- |
| 存储位置 | `<安装目录>\conf\rules.json`（安装目录默认 `%LOCALAPPDATA%\Programs\UncleNovel`） |
| 文件格式 | UTF-8 的 **JSON 数组**，每个元素是一条 `AnalyzerRule`；`[]` 表示无书源 |
| 加载时机 | 应用启动时 `RuleManager` 静态初始化调用 `RuleHelper.loadRules(...)`；**改文件后需重启应用** |
| 应用内导入 | 「书源管理 → 导入」（选本地 JSON 文件 / 从剪贴板）或「网络导入」（填 JSON 的 http 直链） |
| 导入规则 | 数组=批量导入（按 `site` 主机名去重）；单个对象=新增/覆盖同 site 规则；只接受 `isEffective()` 的规则 |
| 生效条件 | 规则需 `enabled: true` 且 `search` 节点有效，才会参与「全网搜书」；`audio: true` 的规则只用于有声书 |

> 小贴士：`enabled: false` 的规则可以被导入、显示在列表里，但不参与搜索。想「先导入再挑着启用」时，把候选规则都设 `enabled: false` 即可。

## 2. 一条规则的完整结构（最小可解析示例）

```json
[
  {
    "name": "示例书源（导入后请改成真实站点）",
    "site": "https://www.example-novel.com/",
    "group": "自定义",
    "enabled": true,
    "audio": false,
    "weight": 10,
    "params": { "userAgent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/126.0" },
    "search": {
      "params": {
        "url": "https://www.example-novel.com/search.php?keyword={{keyword}}&page={{page}}",
        "method": "GET",
        "charset": "UTF-8",
        "dynamicDelayTime": 500
      },
      "list": "//div[@class=\"book-item\"]",
      "detail": {
        "url": "///h3/a/@href",
        "title": "///h3/a/text()",
        "author": { "rule": "///p[@class=\"author\"]/text()", "replace": ["作者：##"] }
      }
    },
    "detail": {},
    "toc": {
      "list": "//div[@id=\"list\"]/dl/dd",
      "name": "///a/text()",
      "url": "///a/@href",
      "filter": true,
      "reverse": false,
      "autoNext": false,
      "enableNext": false
    },
    "content": {
      "content": "//div[@id=\"content\"]/text()",
      "enableNext": false,
      "next": "xpath://a[text()~='.*?下[一]{0,1}[页节].*']/@href"
    }
  }
]
```

字段含义：

| 顶层字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 书源显示名（任意，建议带站点标识） |
| `site` | string | 站点主页 URL；**app 用它做唯一键与去重**，必填 |
| `group` | string | 分组/备注（可省略） |
| `enabled` | boolean | 是否启用（搜索只取 true） |
| `audio` | boolean | `true`=有声书源；文本小说为 false |
| `weight` | int | 搜索排序权重，越小越靠前（默认 0） |
| `params` | object | 全局请求参数：`userAgent` / `cookie` / `dynamic` / `enabledProxy` / `autoReferer` |
| `search` | object | **搜索规则**（见 §3） |
| `detail` | object | 详情页解析规则（打开书籍时用；可为 `{}`） |
| `toc` | object | 目录解析规则（见 §4） |
| `content` | object | 正文解析规则（见 §5） |

## 3. 搜索规则 `search`

```json
"search": {
  "params": {
    "url": "https://站点/search.php?keyword={{keyword}}&page={{page}}",
    "method": "POST",
    "charset": "GBK",
    "mediaType": "application/x-www-form-urlencoded",
    "body": "searchkey={{keyword}}&page={{page}}",
    "headers": { "Referer": "https://站点/" },
    "dynamicDelayTime": 500
  },
  "list": "css:div.bookbox",
  "detailPage": "css:div > a@href",
  "detail": {
    "url": "css:h4 > a@href",
    "title": "css:h4 > a@text",
    "author": { "rule": "css:div.author@text", "replace": ["作者：##"] }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `params.url` | 搜索地址，`{{keyword}}` 由 app 替换为**已 URL 编码**的关键词；`{{page}}` 为页码 |
| `params.method` | `GET`（默认）/ `POST`；POST 时用 `params.body` |
| `params.body` | POST 表单内容，同样支持 `{{keyword}}`/`{{page}}` |
| `params.charset` | 站点编码：`UTF-8`、`GBK`…；留空按响应头/网页 meta 猜测（建议显式写） |
| `params.headers` / `mediaType` | 自定义请求头（如 `deviceinfo`、`Referer`）与 Content-Type |
| `params.dynamic` | `true` 表示动态渲染页面，**本机未内置 PhantomJS/Chromium 驱动，dynamic 规则不可用**，请保持 false/省略 |
| `list` | 搜索结果「条目」选择器：命中多个节点，每个节点=一本书 |
| `detail` | 在**每个列表条目内**解析书信息（`url` 必填，其余尽量填） |
| `detailPage` | 当列表条目中没有书目链接时，用它取详情页 URL（一般用不到） |

`search.detail` 常用子字段：`url`（书页地址，必填）、`title`、`author`、`category`、`state`、`wordCount`、`introduce`、`latestChapterName`、`latestChapterUrl`、`coverUrl`、`broadcast`、`updateTime`。

> ⚠️ 给字段加 `"page": "detail"` 会让 app **为每条搜索结果各抓一次详情页**（如 365 小说网原规则 48 条结果≈55 秒）。只有确实需要该字段时才用，或把它挪到顶层 `detail`。

## 4. 目录规则 `toc`

```json
"toc": {
  "params": { "charset": "UTF-8", "headers": {} },
  "list": "css:div#list > dl > dd",
  "name": "css:a@text",
  "url": "css:a@href",
  "filter": true,
  "reverse": false,
  "autoNext": false,
  "enableNext": false,
  "next": "xpath://a[text()~='.*?下[一]{0,1}[页节].*']/@href"
}
```

| 字段 | 说明 |
| --- | --- |
| `list` | 章节条目选择器 |
| `name` / `url` | 在**每个章节条目内**取章节名 / 章节链接（相对链接会被自动补全为绝对地址） |
| `filter` | 是否过滤明显不是章节的条目（建议 `true`） |
| `reverse` | 是否反转章节顺序 |
| `autoNext` / `enableNext` / `next` | 多页目录：`next` 取下一页链接；`autoNext=true` 自动翻页 |
| `detailPage` | 多页目录的特殊入口（一般不用） |
| `blackUrls` | 要跳过的 URL 列表（可选） |

## 5. 正文规则 `content`

```json
"content": {
  "params": { "charset": "UTF-8" },
  "content": "//div[@id=\"content\"]/text()",
  "enableNext": true,
  "next": "xpath://a[text()~='.*?下[一]{0,1}[页节].*']/@href"
}
```

| 字段 | 说明 |
| --- | --- |
| `content` | 正文选择器；最省事可写 `"auto:1"`（自动识别正文容器，365 小说网规则即如此） |
| `enableNext` / `next` | 正文分页：`next` 取「下一页」链接，`enableNext=true` 时自动拼接后续页 |
| `removeTitle` | 是否去掉正文里重复的章节标题（可选） |
| `traditionToSimple` | 繁体转简体（可选） |
| `delayTime` | 请求间隔（毫秒，可选） |

## 6. 选择器（CommonRule）语法

`list`/`rule`/`name`/`url`/`content` 等字段都接受「规则字符串」或「规则对象」，app 支持以下匹配器（`RuleConstant`）：

| 前缀 | 匹配器 | 示例 |
| --- | --- | --- |
| `//` 或 `xpath:` | XPath（JsoupXpath） | `//div[@class="bookbox"]`、`xpath://a[text()~='.*?下一页.*']/@href` |
| `css:` | CSS 选择器（Jsoup，支持 `>` 与 `@属性`/`@text`） | `css:div.bookinfo > h4 > a@href`、`css:a@text` |
| `$` 或 `json:` | JSONPath（用于 API 型书源） | `$.data.ret_data`、`$..content` |
| `regex:` | 正则 | `regex:作品名称：(.*?)##$1` |
| `auto:` | 正文自动识别（仅 content 常用） | `auto:1`、`auto:2` |
| 纯文本 | 默认文本匹配 | 少用 |

**XPath 相对路径**：`///` 开头表示「相对当前条目节点」的路径（等价于在条目内继续匹配），例如列表条目里再取书名用 `///h3/a/text()`。

**规则对象**（字段组合使用）：

```json
{
  "rule": "css:div.bookdesc > a@href",
  "script": "result = result + (result.endsWith(\"/\") ? \"index.html\" : \"\");",
  "replace": ["作者：##"],
  "page": "search"
}
```

| 键 | 说明 |
| --- | --- |
| `rule` | 匹配器规则（见上表） |
| `script` | 匹配后执行的 JS（Nashorn），可用变量：`result`（上一步结果）、`source`（原始页面文本）、`url`（当前 URL）、`utils`（工具类：`utils.get/post/request/bytes/toJson/match/matchList/absUrl/log`）；最后 `result` 的值即输出 |
| `replace` | 文本替换集合，元素格式为 `"正则##替换文本"`（替换文本可空；`$0`/`$1` 引用分组），如 `["<em>##", "</em>##"]` 表示删掉 `<em>`/`</em>` |
| `page` | 指定在「搜索页 `search`」或「详情页 `detail`」上匹配（可选） |

> `replace` 语法说明：`正则##替换`，其中 `##` 是分隔符；`"作者：##"` 即删掉「作者：」前缀。

## 7. 自建书源流程（推荐）

1. **浏览器 F12 找搜索接口**：在站点搜索框搜一本书，Network 里看请求是 GET 还是 POST、参数名、编码（UTF-8/GBK）、是否需要 UA/Referer/Cookie。
2. 复制响应 HTML（或 JSON）到本地，对着 DOM 写选择器：
   - 搜索结果列表：`//div[@class="..."]` 或 `css:div.xxx`；
   - 结果内的书名/作者/书页链接（相对路径用 `///`）；
   - 书页的目录容器与章节链接；
   - 章节页的正文容器（优先 `//div[@id="content"]/text()`，不行再用 `auto:1`）。
3. 先只填 `search`（`detail`/`toc`/`content` 可先留空对象），导入 app 里搜一次，确认能出书；
4. 再补 `toc` 与 `content`，用「下载」验证目录章数与正文是否正常；
5. 规则自检（不启动 GUI，直接用应用自带 jar）——见 §8。

**常见坑 checklist**

- [ ] `site` 与规则里实际请求的站点一致（用于去重/显示）；
- [ ] 站点是 `http` 还是 `https`（有的站 https 直接 404，如书趣阁新域名必须 http）；
- [ ] 搜索是 GET 还是 POST，参数名照抄（如 `wd`/`keyword`/`searchkey`/`q`）；
- [ ] 编码：GBK 站必须写 `"charset": "GBK"`，否则乱码；
- [ ] 需要 UA 的站，在顶层 `params.userAgent` 写浏览器 UA；
- [ ] 不要用 `params.dynamic=true`（本机无浏览器驱动，会报 `Cannot run program`）；
- [ ] 目录页 URL 是「书信息页」还是「目录页」（如 365 小说网 `/book/1/` 是信息页，`/book/1/index.html` 才是目录，需要用 script 补）；
- [ ] 正文换行：HTML 用 `text()`/`auto:` 一般正常；JSON API 若返回字面量 `\r\n`，用 `script` 清洗；
- [ ] 规则里不要塞无关字段；保存前用 `TestRules` 验证一遍能被 `RuleHelper` 解析。

## 8. 不启动 GUI 的自检方法（用安装目录自带 JDK11 + jar）

```powershell
$inst = "$env:LOCALAPPDATA%\Programs\UncleNovel"
$cp   = "$inst\runtime\modules\*"
$nr   = "任务-uncle-novel优化-2026-10-25\工具\net-rules"

# 编译（一次性）
& "$inst\runtime\bin\javac.exe" -encoding UTF-8 -cp $cp "$nr\TestRules.java" "$nr\SearchTest.java" "$nr\DownloadTest.java"

# A. 规则能否被 app 解析
& "$inst\runtime\bin\java.exe" -Dfile.encoding=UTF-8 -cp "$cp;$nr" TestRules "你的规则.json"
#   期望：loadRules 返回条数 = 数组长度；每条 isEffective=true、searchEffective=true

# B. 能否搜出书
& "$inst\runtime\bin\java.exe" -Dfile.encoding=UTF-8 -cp "$cp;$nr" SearchTest "你的规则.json" "斗破苍穹" "out\search.json"
#   期望：count > 0，且书名/作者正确

# C. 能否下载（siteRegex 用规则 site 的一部分）
& "$inst\runtime\bin\java.exe" -Dfile.encoding=UTF-8 -cp "$cp;$nr" DownloadTest "你的规则.json" "你的站点域名" "斗破苍穹"
#   期望：toc count>0、content length>0（正文不是站点说明/验证码）
```
