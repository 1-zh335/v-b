## 2. 方法与口径

### 2.1 素材编码：GB18030 正文 + UTF-8 标题行“混合编码”

6 个 txt 都不是纯 GB18030：正文是 GB18030，而 `=== 标题 ===` 行、`本书来自:` 行等是 **UTF-8 字节**直接混在文件里。整文件按 GB18030 严格解码会在第 67 字节左右失败；按 GB18030 读出的标题是乱码，例如：

```
=== 绗\ue0ff竴绔?閭ｅぉ璧蜂簡寰堝ぇ鐨勯浘 ===     ← GB18030 硬解（乱码）
=== 第一章 那天起了很大的雾 ===                ← 逐行 UTF-8 解码（正确）
```

基准采用的逐行解码策略（0 解码异常）：

1. 逐行先试 UTF-8 strict，且结果含汉字 → 视为 UTF-8 混入行，采用 UTF-8；
2. 否则试 GB18030 strict，含非 ASCII 字符 → 采用 GB18030 正文；
3. 仍失败才 GB18030 `replace` 并计数（本次全部 0 行）。

| 素材 | UTF-8 混入行（含汉字） | GB18030 正文行 | 纯 ASCII 行 | 解码异常 |
|------|-----------------------:|---------------:|------------:|---------:|
| 地煞七十二变 | 333 | 45,487 | 15 | 0 |
| 大奉打更人 | 953 | 132,675 | 744 | 0 |
| 完美世界 | 2,053 | 185,962 | 258 | 0 |
| 深海余烬.txt | 722 | 41,290 | 44 | 0 |

### 2.2 候选规则（与任务说明一致，逐行 `re.match`）

```
R1  ^\s*={2,}.*={2,}\s*$
R2  ^[ \t\u3000]{0,4}第[0-9零〇一二两三四五六七八九十百千万壹贰叁肆伍陆柒捌玖拾佰仟]{1,12}[章节回卷集部篇][^\n]{0,80}$
R3  ^.*《[^》]{1,30}》[ \t\u3000]{0,4}第[0-9零〇一二两三四五六七八九十百千万壹贰叁肆伍陆柒捌玖拾佰仟]{1,12}[章节回卷][^\n]{0,80}$
```

### 2.3 标题清洗（与应用补丁一致）

1. 去首尾空白；2. 去首尾 `=`；3. 去掉行首《书名》≤30 字前缀（仅当《…》后紧跟章号/序/番外等才去，避免误伤正文引用）；4. 在“正在手打中”或“免费阅读”处截断，丢弃其后内容（因此 `第一百三十四章  火中盛宴免费阅读：，！` → `第一百三十四章 火中盛宴`）；5. 连续空白归一为单个半角空格。

### 2.4 去重 / 分章边界 / 字数口径

- **去重**：清洗后标题与上一保留标题完全相同（连续重复）则合并为一章；非连续重复不合并（《蛊真人》因此多出 1,174 章，见 §6 风险 2）。
- **分章边界**：本章正文 = 本章标题行下一行起，至下一章标题行前止；末章到文件末尾。
- **每章字数（估算）** = 全文去空白字符数（扣除 R1 标题行）÷ 去重后章节数。对 R2/R3 这类只命中部分位置/水印的规则，该数值只是“总字数÷命中数”，无分章参考意义（表中标“不可用”）。

## 6. 风险点（写断言前必读）

1. **混合编码是最大坑**：`===` 标题行是 UTF-8 字节混在 GB18030 正文里。整文件按 GB18030 读 → R1 仍能命中（`=` 是 ASCII），但章节名是乱码；R2 完全失配。若应用只做单编码整文件读取（EncodingDetect 选 GB18030），则 **断言章节名必须用乱码形态或只断言数量**；若补丁实现逐行 UTF-8 优先解码，则用本报告 §3 的名称。本基准采用后者（逐行解码，0 异常）。
2. **《蛊真人》大段重复**：3,554 个 `===` 行只有 2,378 个唯一标题；连续去重后 3,552。若把 3,552 当“真实章数”写死，后续补丁做全局去重会直接打脸。建议断言注明口径，或先与产品确认去重策略。
3. **作者话被算成章节**：大奉 22 / 完美世界 23 / 深海余烬 1 / 蛊真人 41。尤其《完美世界》最后两个 `===` 是“新书，11月1日上传”“我的新书《圣墟》已上传”，规则产出末章不是正文末章（真实末章：第两千零一十四章 独断万古（大结局））。
4. **章号不单调/有缺号**：地煞按卷重置 5 次（末章编号 59、最大 129）；大奉重置/重复 16、缺号 7 段；完美世界重置/重复 40、缺号 38 段且异形章号多（`第雷一千六百二十六章`、`第一千六百三朽十二章` 等）；深海缺 4 个编号；苟在妖武缺 7 个 + 1 处重复（第636章）；蛊真人按卷重置 22 次。**不要用“最大章号 = 章节数”或“章号连续递增”做断言。**
5. **R2/R3 不能选为主规则**：R2 命中都是正文内重复标题/水印（各文件去重后分别只有 1/9/73/56/634/5 个，蛊真人 R2 仅覆盖到 34% 行），其中苟在妖武 R2 只能切出前 636 章（58%）；R3 命中是正文引用（《人祖传》《周纪》《地煞七十二变》），去重后 7/1/0/0/0/32。若应用误命中这两条规则，会把小说切成大量伪章节。建议测试断言“选中的规则 = R1”或“章节数 = 预期值”。
6. **docx 标题乱码不可逆**：转换件只能断言 721 章数量与顺序，名称断言请用同名 txt（§3.4）；两者的 722 行差异全部来自标题/来源行的编码损坏。
7. **大文件性能**：蛊真人 24.7 MB / 654,038 行 / 1,104 万非空白字符，是其余素材的 1.4–9.7 倍；应用按 512 KB 分块解析并产出 3,552 章，测试导入耗时需单独放宽/超时设置。
8. **匹配口径差异**：本分析按“行”匹配（去掉 `\r` 后逐行 `re.match`）；应用是在 512 KB 块上 `Pattern.MULTILINE` 全文 find 并做块边界处理。对这三条规则，逐行与分块的命中集合应一致；但若补丁额外做标题合并/过滤，预期章节数以补丁最终行为为准，本基准 = “R1 匹配 + 清洗 + 连续去重”口径。
