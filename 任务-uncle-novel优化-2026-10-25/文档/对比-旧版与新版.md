# 对比：旧版 4.x / 官方 5.0.44 / 优化版 5.0.44

> 本文档对比三个版本：**用户本机保留的旧版 4.x（2020 年构建）**、**官方 5.0.44 原版**、**本优化版 5.0.44**。
> 前两份数据来自实际安装副本的检查与实测；旧版部分测量条件与新版不同，见 §6 局限。
> 关联文档：[README.md](README.md)、[修改说明.md](修改说明.md)、[对比报告.md](对比报告.md)（官方原版 vs 优化版的详细对比）。

## 3. 主要差异解读

### 3.1 从 4.x 到 5.x：功能与界面大幅增强，代价是内存

- **功能**：5.x 新增「全网搜书」「书源管理」「软件设置（主题/语言/字体/下载/备份/代理/热键）」、有声/听书相关模块、多套主题（主页 14 套、阅读 9 套）、自定义阅读主题 CSS 等。
- **界面**：深色顶栏 + 浅色内容，侧栏结构从“找书/读书/下书”升级为“找书/读书/下书/书源/设置”。
- **代价**：运行时由 JRE 8 32 位（JavaFX 8）升级为 JDK 11 64 位 + JavaFX 17.0.2，**RSS 从约 166 MB 升至约 700–740 MB**；启动耗时量级也更高（UI 就绪约 5 秒）。这是框架升级与功能增加的整体代价，不是某处配置问题。

### 3.2 启动器与更新机制

| 版本 | 启动器 | 更新地址 | 失效后的行为 |
| --- | --- | --- | --- |
| 旧版 4.x | fxlauncher | `http://uncle-novel.unclezs.com/app/app.xml` | `launcher.log` 记录联网更新失败栈；应用仍可启动 |
| 官方 5.0.44 | exe4j 8.0 + jfx-launcher | `https://update-uncle-novel.unclezs.com/novel/prod/` | 记录 `更新失败`（UnknownHost），继续启动；但 `hasNew` 保持 true → **每次启动弹更新日志** |
| 优化版 5.0.44 | 同官方 | `http://127.0.0.1:1/` | 记录 `更新失败`（Connection refused，立即返回），继续启动；**无弹窗**（应用层调用已移除） |

旧版 `logs\launcher.log` 与官方 `logs\log-system.log` 都出现过更新服务器域名解析失败的栈，说明更新服务在 4.x 时期之后即已停止维护。

### 3.3 设置与主题机制

- 旧版：设置集中在 `conf\application.json`，主题为 `theme\theme.css` / `reader.css` 两个可直接编辑的 CSS。
- 新版：设置拆分为 `conf\conf.json` 的结构化分组；主题为内置 14（主页）/ 9（阅读）套 + `conf\reader-theme.css` 自定义主题 CSS，可调项更多。
- 因此旧版的设置/主题**不能直接迁移**到新版，需要在新版界面里重新设置。

### 3.4 数据库与数据迁移

- 旧版 `core.db` 使用 MyBatis + 旧表结构（`book` 12 列，含本地文件路径 `path`、章节索引 `chapter_index` 等）。
- 新版 `core.db` 使用 ORMLite + 新表结构（`book` 13 列，改为 `url/author/group/currentPage/charset/local/txtTocRule…`，并新增 `search_engine`、`txt_toc_rule`、`download_history`、`audio_book` 等表）。
- **结论：旧版 `core.db` 不能直接拷到新版使用**（表结构完全不同，强行替换会导致书架/书源异常）。旧书需要按下述流程重新导入。

## 4. 旧版用户数据与旧书恢复方案

### 4.1 旧版里有什么（用户数据）

| 数据 | 内容 |
| --- | --- |
| 书架 | `book` 表 1 本：**《大王饶命》**（原文件路径 `E:\小说\大王饶命.txt`，该文件已不在本机） |
| 文字书源 | `search_text_rule` 3 条：bxwx8.la（笔趣阁）、x23qb.com（铅笔小说）、shencou.com（神凑小说） |
| 有声书源 | `search_audio_rule` 10 条：audio699 / ting22 / tingchina / ting55 / ixinmo / 520tingshu / ting56 / ting89 / ysts8 / lrts.me |
| 正文缓存 | `cache\9ad2a359...\` 下保存了《大王饶命》全部章节正文（`book.json` + 数字命名的章节文件），已实测可读 |

### 4.2 恢复流程（旧书 → 新版）

1. 从旧版 `cache\9ad2a359...\` 读取 `book.json` 与章节文件，按顺序拼接为 TXT：本机实测恢复到 **33 章**，产出 UTF-8 TXT **8,776.3 KB**（GBK 版 6,040.4 KB）；脚本为 `工具\恢复旧版书籍.ps1`，成品在 `旧版数据恢复\大王饶命-恢复-UTF8.txt`（**不进交付 zip**：涉及小说正文版权，仅供用户本人迁移自用）。
2. 打开新版 → 左侧「小说书架」→ 使用「导入本地小说」功能导入该 TXT（源码 `FictionBookshelfView.importBook` 确认新版支持本地 TXT 导入）。
3. 导入后书架会出现该书；阅读进度/书签需重新建立（旧版进度字段与新表结构不兼容）。
4. 旧版书源（3 条文字 + 10 条有声）**不要指望直接复用**：书源站多数已失效；新版可在「书源管理」导入社区维护的书源 JSON（例如 gitee 上的社区书源）。

> 恢复脚本：`工具\恢复旧版书籍.ps1`；恢复出的 TXT：`旧版数据恢复\大王饶命-恢复-UTF8.txt`（UTF-8，8,776.3 KB）与 `旧版数据恢复\大王饶命-恢复-GBK.txt`（GBK，6,040.4 KB）。两者均**不随交付 zip 分发**。

### 4.3 迁移注意事项

- 旧版 `conf\application.json`、`theme\*.css`、`core.db` **都不要直接复制**到新版安装目录（结构不兼容）。
- 新版数据目录 = 安装目录（见 [README.md](README.md) §6），迁移时只搬新版的 `conf\`、`downloads\` 等。
- 旧版可保留不删（约 206 MB），作为正文缓存来源；确认恢复完成后可自行清理。

## 5. 结论

> **旧版轻量（RSS 约 166 MB）但功能少、数据封闭（MyBatis 旧表结构、书源/主题强绑定旧版）；新版功能完整、界面现代、主题与书源可扩展，但内存占用显著更高（约 700 MB 量级）、启动更重；两者数据不通用，旧书需要按 §4 的恢复流程重新导入。**

- 想继续用旧书：按 §4 从旧版 cache 恢复 TXT → 新版「导入本地小说」。
- 想保留旧版体验：旧版安装可继续保留（但更新服务已死、书源多失效、无新功能）。
- 想日常使用：推荐本优化版 5.0.44（无更新弹窗、字体错误修复、体积更小、首次安装带调优阅读配置；详见 [对比报告.md](对比报告.md)）。

## 6. 局限与待补

1. **旧版测量条件不同**：旧版为另一份安装副本、单次启动记录（窗口 2.33 s / UI 5.99 s），与新版“各 3 次交替”的口径不一致；机器负载、磁盘缓存状态不同，启动数据仅作量级参考。
2. **旧版 RSS**（约 166 MB）为单次观察值，未做多轮统计；新版 RSS 见 [对比报告.md](对比报告.md)。
3. 旧版 jar 版本审计（24 个 jar 中有 Manifest 版本者）：jfoenix 8.0.8、controlsfx 8.40.15、mybatis 3.5.3、mybatis-plus 3.3.1.tmp、freemarker 2.3.29、sqlite-jdbc 3.27.2.1、jsoup 1.13.1、jsqlparser 3.1.0、log4j 1.2.17、jacob 1.19、JNativeHook 2.1、slf4j 1.7.30、junit-jupiter 5.3.2、junit-platform-commons 1.3.2、opentest4j 1.1.1、apiguardian 1.0.0；fastjson/hutool-all/garbage/xsoup/chinese-utils/lombok 的 Manifest 未写版本号。
4. 旧版正文缓存已恢复：33 章、UTF-8 TXT 8,776.3 KB（GBK 版 6,040.4 KB），脚本与成品在任务目录；**未做**“恢复文本与原书逐字比对”（原文件 `E:\小说\大王饶命.txt` 已不在本机，无基准可比），建议用户导入后自行抽查章节完整性。
5. 旧版数据库表结构描述来自实际库文件检查；迁移可行性结论“不能直接拷贝”基于表结构差异，未做“强行拷贝后”的破坏性实验。

## 7. 旧版体验在 5.0.44 增强版中的落地（2026-10-27）

旧版 4.x 未做代码级合并（Java 8 + fxlauncher 架构与 5.x 模块化差异过大），采取“**功能等价 + 数据可恢复**”的方式合并：

| 旧版 4.x 能力 | 增强版对应实现 |
|---|---|
| 本地 TXT 打开即读 | 新增 `QuickApp` 入口：桌面「Uncle小说 · 本地TXT快速阅读」快捷方式 / 拖拽 TXT 到 `本地TXT快速阅读.bat` / 右键发送到 / 文件选择框 |
| 章节列表（按章阅读） | 自动识别章节（含 `===` 格式），目录跳转；标题栏显示「章 n/m」 |
| 分页阅读 + 字体/字号/行距可调 | 每章独立分页 + 顶部显示「第 x/y 页」；阅读面板可调字体/字号/行距/页宽/对齐/简繁/主题/动画 |
| 护眼绿阅读背景 | 默认 green 阅读主题（#ceebce 系，与旧版相近） |
| 主题 CSS 可改 | 官方 `conf/reader-theme.css` 自定义主题机制保留 |
| 旧版本地书籍缓存 | `工具\恢复旧版书籍.ps1` 恢复为 TXT 后可直接打开（已恢复《大王饶命》33 章） |

实测（详见 [测试报告.md](测试报告.md)）：6 个 TXT（2.42–23.56 MB）+ 1 个 DOCX 转换件全部可打开、自动分章（331 / 942 / 2050 / 721 / 1094 / 3552 / 721 章）、正常翻页，无错误日志。

代价：5.x 基于 JavaFX 17 模块化，内存占用（约 700–740 MB）无法回到旧版 4.x 的约 166 MB；但本地阅读流程的启动/打开已做精简（欢迎页 1.5–2.6 s，打开 4.5–8.3 s，二次打开走索引缓存）。
