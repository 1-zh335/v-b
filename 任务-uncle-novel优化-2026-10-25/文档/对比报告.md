# 对比报告 —— Uncle小说 v5.0.44 官方原版 vs 优化版

> 本文档给出「官方原版 v5.0.44」与「本优化版」的实测对比、测量方法与局限。
> 结论先行：**功能等价；启动耗时同量级（优化版未见变慢）；主要收益是消除每次启动的更新日志弹窗、更新检查不再等待失效域名、字体加载错误消失、安装体积减少约 25%、内存有上限约束，以及首次安装即带调优阅读配置。** 不宣称启动速度提升。

关联文档：[README.md](README.md)（安装使用）、[修改说明.md](修改说明.md)（技术变更与回退）、[对比-旧版与新版.md](对比-旧版与新版.md)（旧版 4.x / 官方 v5.0.44 / 优化版三方对比）。

## 3. 分项说明

### 3.1 安装体积（-25.6%）

- 原版解压后 205,638,760 B（196.1 MiB / 208 文件，不含运行时生成的 logs/conf.json 等）；优化版 153,715,684 B（146.6 MiB / 206 文件）。
- 差额 51,923,076 B（约 49.5 MiB），主要来自删除两个 Windows 用不到的转换组件：
  - `bin\kindlegen`（macOS，23,163,488 B）
  - `bin\kindlegen_linux`（Linux，28,752,467 B）
- 保留 `bin\kindlegen.exe`（Windows，7,908,160 B，MOBI 导出用）。
- 交付 zip：121.2 MB（127,058,445 字节，224 个条目），SHA256 `371CBA8489175B6105821D45C3AC2341A14E6ECD7616E9486C5832372D52E3AE`（2026-10-27 v2.0 增强版）。
- 统计口径：目录内文件字节数累加（MiB 显示）；不同工具/是否计入 NTFS 簇开销会有小幅差异。

### 3.2 启动耗时（同量级，不宣称提升）

| 阶段 | 原版（n=3，交替） | 优化版（n=3，交替） |
| --- | --- | --- |
| 启动器 splash 可见 | 约 1.3–1.5 s | 约 1.3–1.5 s |
| 主窗口可交互（UIA 找到「小说书架」） | 4.76–6.33 s（中位 6.33 s） | 4.96–5.20 s（中位 5.20 s） |

结论：**两版同量级，优化版未见变慢**。启动瓶颈主要在 JavaFX 初始化（约 4–6 s 量级），本次优化未触及该路径；JVM 参数亦未带来可测量的启动收益（G1 与 SerialGC 对比也未观察到量级差异）。因此本文不把“启动提速”作为优化收益。

> 说明：机器测试期间有后台负载，且样本仅 3 次/版，绝对秒数不可作为稳定基准；更早的基线轮次记录为 splash 1.0–1.3 s、UI 3.8–4.9 s（不同时段/负载），同样只适合同机相对参考。

### 3.3 更新日志弹窗（消除）

- 机制（字节码/源码核实，详见修改说明 CHG-01）：启动器检查更新失败时 `newVersion` 保持默认 `true`，以 `hasNew=true` 传给应用；应用 `App.start()` 调用 `UpdateUtils.checkForUpdate(stage)` 弹出「当前版本 - V5.0.44」更新日志。由于更新域名已失效，**原版每次启动都会弹**。
- 优化版对该调用做 4 字节等长 NOP 替换后，不再弹窗。
- 证据：
  - UIA 自动化统计窗口内元素数：原版 **83** → 优化版 **71**（弹窗相关元素消失）；
  - 窗口截图对比：原版截图中可见「当前版本 - V5.0.44」对话框（`截图\原版\`），优化版截图中无（`截图\优化验证\`、`截图\安装验证\`、`截图\最终验收\shot-002546.png`）；
  - 应用功能/设置界面正常（UIA 点击「小说书架」「软件设置」验证；设置页截图 `截图\最终验收\shot-002552.png`）。

### 3.4 日志与字体（错误消除）

| 项 | 原版 | 优化版 |
| --- | --- | --- |
| `logs\log-error.log` | 16 条 `加载pingfang-simple-bold.ttf字体失败`（10:31–10:56 多次启动记录） | **0 字节**（无记录） |
| `conf\font.css` | 生成 `.root{-fx-font-family: 'System';}` 等 | `.root{-fx-font-family: 'Microsoft YaHei';}`（调优配置生效） |

根因定位（修改说明 CHG-05）：字体文件本身有效（`OTTO` OpenType，10,646,300 B），ASCII 路径下 `Font.loadFont` 可加载为 `.PingFang SC`；含中文的路径下返回 `NULL`。原版安装/解压在本工程中文路径下，故每次启动报错。优化版部署到纯 ASCII 路径后错误消失。

### 3.5 内存与 JVM 参数（上限约束，非提速）

- RSS：两版均约 700–740 MB（JavaFX 应用本身开销；优化前后无显著差异）。
- 基线堆数据：committed 约 378–415 MB，used 约 40–55 MB；`-Xms128m/-Xmx1024m` 主要限制最坏膨胀，不预占 1 GB。
- 验证：应用运行时用自带 `runtime\bin\jcmd.exe`：
  - `VM.flags` 实测 `MaxHeapSize=1073741824`（1 GB）、`MaxMetaspaceSize=268435456`（256 MB）、`ReservedCodeCacheSize=134217728`（128 MB），并可见 `-Xms128m` 等；
  - `VM.system_properties` 实测含 `prism.lcdtext=false`、`java.net.useSystemProxies=true`。
- 对比实验：G1 与 SerialGC 对 RSS/启动未观察到量级差异 → 不把 GC 调优作为收益。

### 3.6 更新检查链路（快速失败）

| 项 | 原版 | 优化版 |
| --- | --- | --- |
| 请求地址 | `https://update-uncle-novel.unclezs.com/novel/prod/conf/app.json` | `http://127.0.0.1:1/conf/app.json` |
| 失败类型 | `UnknownHostException`（DNS 解析失败，可能等待超时） | `ConnectException: Connection refused`（本机回环端口无监听，立即返回） |
| 失败后行为 | 捕获异常 → `严重: 更新失败` → 继续初始化并启动应用 | 同（只是更快失败） |
| 用户可见影响 | 每次启动弹更新日志（见 §3.3） | 无弹窗；日志仍有 1 条「更新失败」（**预期行为**） |

DNS 复核（`Resolve-DnsName`）：`uncle-novel.unclezs.com`、`app.unclezs.com` 返回“域名不存在”，`update-uncle-novel.unclezs.com` 返回超时；三个域名均不可用。

### 3.7 界面渲染

`-Dprism.lcdtext=false` 关闭 Prism 的 LCD 次像素文字渲染，中文界面文字边缘不再出现红/蓝色镶边（截图对比见 `截图\` 目录下的裁剪图）。属观感优化，对性能无实质影响；如更喜欢系统默认渲染，删除该参数即可（见修改说明 CHG-03 回退）。

### 3.8 部署与首次安装配置

- 官方原版：`Setup.exe` 默认装到 `{Program Files}`（需管理员，路径可能含中文），或解压后手动建快捷方式（起始位置易配错 → 数据目录漂移）。
- 优化版：`安装到本机.bat` → `%LOCALAPPDATA%\Programs\UncleNovel`（ASCII、免 UAC）+ 桌面/开始菜单快捷方式（起始位置=安装目录）；首次安装由 `初始化配置.ps1` 写入调优 `conf\conf.json`，覆盖安装保留 `conf\core.db` 与 `conf\conf.json`。
- 端到端测试：解压 zip → 双击安装 → 多条 `[OK]`（程序文件复制 / 已生成调优配置 / 快捷方式）→ 快捷方式创建 → 启动正常 → 覆盖安装保留 `core.db` 与 `conf.json`（哈希不变），**已通过**；全新安装时 `conf\conf.json` 实测为调优值，设置页 UIA 文本实测「系统字体 = Microsoft YaHei」「单任务线程数量 = 2」「失败重试次数 = 1」「下载文件保存位置 = 安装目录」。

## 6. 局限与未验证项

1. **单机单配置**：只有 1 台测试机（i5-1135G7/16 GB/Win11/150% 缩放），不同 CPU、磁盘、杀软、系统版本都会改变启动时间与内存，**绝对值不可跨机比较**。
2. **样本量小**：启动对比为各 3 次交替，且测试机有后台负载；未做多次冷启动/热启动分离统计、无置信区间。优化版启动数字与更早基线轮次存在差异（不同时段环境不同），文档只做“同量级”表述。
3. **计时口径依赖 UIA**：UI 就绪以“能访问到「小说书架」元素”为准，受窗口渲染/无障碍树构建影响；与“人眼感觉可用”可能有偏差。
4. **RSS 为瞬时值**：进程树 WorkingSet 随时间/GC 波动，单次数值不代表稳定占用；优化版堆数据为 2026-10-27 单次代表测量（committed 约 404 MB / used 约 41 MB），未做多轮统计。
5. **UIA 元素数**不是功能指标：83→71 只用于佐证弹窗消失，不能推断其他界面变化。
6. **体积单位/口径**：按文件字节累加并换算 MiB；与资源管理器显示、NTFS 实际占用可能存在差异。
7. **未做完整功能回归**：本次验证覆盖启动、主界面、设置、安装/覆盖安装/卸载、字体、更新链路；**未逐项回归**下载/解析、TXT/EPUB/MOBI 转换、TTS/听书、书源搜索、内置备份等业务功能（改动未触及这些代码路径，但不等同于已验证）。
8. **未验证/未实施**：AppCDS（需优雅退出生成归档，成本高、收益不确定）、全局 CSS 换肤、TTS 源替换、125% 高 DPI 布局（上游 issue #69）、长时间运行稳定性、多显示器场景。
9. **更新检查时延**：只验证了失败类型从 DNS 失败变为连接拒绝；本机日志为秒级，无法给出精确差值（两者均 ≤1 s），该耗时随网络/DNS 环境变化很大，优化目标是消除最坏情况（DNS 慢/被劫持）的长等待。
10. **旧版对比**（4.x）数据来自另一份本机旧安装，测量条件与本次不同（见 [对比-旧版与新版.md](对比-旧版与新版.md)），只作参考。

## 7. 结论

1. **功能等价**：业务代码只有 1 处 4 字节等长补丁（移除更新日志弹窗调用），其余为配置/部署/体积调整；启动、主界面、设置、安装/卸载均验证通过。
2. **启动速度**：同量级，**优化版未见变慢**；不以“提速”作为卖点（瓶颈在 JavaFX 初始化）。
3. **实际收益**：
   - 消除每次启动必弹的更新日志对话框（体验最明显）；
   - 更新检查不再等待已失效域名的 DNS 超时（改为本地立即失败），且日志中的「更新失败」属预期；
   - 安装到纯 ASCII 路径后内置字体正常加载，`log-error.log` 不再出现字体错误；
   - 安装体积 196.1 → 146.6 MB（-25.6%）；
   - JVM 参数提供堆/元空间/代码缓存上限，行为更可预测；
   - 首次安装即写入调优阅读配置（微软雅黑 20 号/行距 0.2/下载线程 2），且覆盖升级不覆盖用户设置。
4. **建议**：把本优化版作为“官方 5.0.44 的本地可用化封装”使用；如需官方原版行为，按修改说明逐项回退即可；重要数据（`conf\core.db`、`conf\conf.json`、`downloads\`）请按 README §6 定期备份。

## 8. 2026-10-27 本地 TXT 阅读增强（v2.0）

在原有“安装后优化”之上，为满足本地 TXT 阅读需求新增：

1. **打开即读**：新增 QuickApp 入口（桌面快捷方式 / 拖拽 / 右键发送到 / 文件选择框），不再需要「导入→预览→加入书架」。
2. **启动路径精简**：跳过托盘/全局热键/自定义字体初始化，并用轻量欢迎页代替官方首页；欢迎页 1.5–2.6 s，主界面读取就绪 4.5–8.3 s（随文件大小）。
3. **编码与章节修复**：GB2312/GBK 统一按 GB18030 解码；修复 `=== 绗… ===` 这类 UTF-8→GBK 乱码标题（如 `第1章 七十二变`）；支持标准章/节/卷、`===` 分隔、书名前缀等格式。
4. **索引缓存**：24 MB / 65 万行文件首次索引 854 ms，二次 49 ms。
5. **分页显示**：标题栏 `书名 · 章节名（第 x/y 页 · 章 n/m）`，每章独立分页，页宽/字号/行距/窗口调整即时重排。
6. **素材实测**：6 个 TXT + 1 个 DOCX 转换件全部通过（详见 [测试报告.md](测试报告.md)），最大文件 23.56 MB。

> 结论：v2.0 后本版同时具备「官方在线功能（书源/下载/听书）」与「旧版式本地 TXT 打开即读」两种能力，且本地阅读路径的启动与打开速度明显优于「导入书架」流程。
