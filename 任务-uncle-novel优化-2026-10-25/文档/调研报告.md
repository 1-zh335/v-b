## 2. 真实的打包与启动链路（源码核实，纠正常见误解）

**不是 jpackage + NSIS**，而是：

```
Uncle小说.exe  (exe4j 8.0, wrapperType=embed, executableMode=gui,
                singleInstance=true, redirectStderr=false)      ← buildSrc/.../windows/exe4j.vm
   └─ JVM: runtime/  (jlink 生成, JAVA_VERSION=11.0.18, 含 JavaFX 模块)
        vmArgs: -Djava.util.logging.config.file=conf/jul.properties
                --add-modules ALL-SYSTEM
                -Dfile.encoding=UTF-8
                --add-opens=java.base/java.lang=com.unclezs.jfx.launcher
                -include-options conf/launcher.vmoptions      ← 唯一的用户可编辑 JVM 参数入口
   └─ mainClass: com.unclezs.jfx.launcher.Launcher  (jfx-launcher 1.1.11-SNAPSHOT, 源码未公开)
        ├─ 读本地 conf/app.json → 联网同步 https://update-uncle-novel.unclezs.com/novel/prod/
        └─ 启动 com.unclezs.novel.app.main.App（JavaFX 11/17 模块化应用，libraries 在 runtime/modules）
```

- 安装包为 **Inno Setup**（`iss.vm`，`DefaultDirName={autopf}\uncle-novel`，简体中文语言包），默认需 UAC。
- **无 `app/*.cfg`**（非 jpackage）。JVM 参数唯一入口 = `<安装目录>\conf\launcher.vmoptions`，本机实测生效（jcmd 确认 `-Xmx` 等参数被 JVM 接受）。
- `uncle-novel.jar`（28 KB）是启动器 jar，**被 exe4j 内嵌进 exe**；磁盘上的外部同名文件实际不参与启动（本机实测：改名后应用照常启动）。

## 3. 数据目录机制（决定了「安装/迁移/备份」怎么做）

〔源码〕`ResourceManager.WORK_DIR = new File(".").getAbsolutePath()`：

```
<工作目录>/
├─ conf/     app.json、core.db（SQLite 数据库：书架/书源/规则）、conf.json（设置）、font.css、launcher.vmoptions、jul.properties
├─ fonts/    启动时自动加载的字体
├─ logs/     logback 日志 + java.util.logging 的 log-system.log
├─ caches/   TTS 等缓存
├─ downloads/ 默认下载目录
├─ backup/   备份目录
├─ plugins/  插件目录
└─ bin/      kindlegen.exe
```

推论〔推断，行为实测一致〕：**从哪个目录启动，数据就写到哪个目录**；快捷方式「起始位置」不是安装目录时会出现「书架/设置丢失」类问题。整目录搬迁 = 迁移数据；备份 = 打包整个目录。

## 4. 本机实测结论

| 项目 | 结果 |
|---|---|
| 更新域名 | `uncle-novel.unclezs.com`、`update-uncle-novel.unclezs.com`、`app.unclezs.com` **DNS 全部无法解析**（2026-10-25 实测）→ 每次启动更新检查必失败 |
| 启动器行为 | 更新检查失败后仍继续启动应用；但启动器内部 `newVersion` 字段默认为 `true` 且失败时不会归零 → 传到应用的 `hasNew=true` → **每次启动都弹「当前版本 - V5.0.44」更新日志对话框** |
| 数据库 | 官方包内 `conf/core.db` 本机实测 `PRAGMA integrity_check = ok`（书源 3 条、txt 目录规则 18 条）；网传 issue #75/#84/#86 的「数据库损坏导致无法启动」在本机下载的官方 5.0.44 包中**未复现** |
| 字体 | 内置 `fonts/pingfang-simple-bold.ttf` 实际是有效 OTF（`Font.loadFont` 在 ASCII 路径可加载为 `.PingFang SC`）；但在**含中文字符的安装路径**下加载失败并产生日志错误 |
| 高 DPI | 本机 1920×1080、150% 缩放；JavaFX 场景按 1.5 倍渲染，界面显示正常 |
| 内存 | 5.0.44 运行 RSS 约 700–740 MB（堆 committed 约 380–420 MB、Used 约 40–60 MB）；JVM 参数调整对 RSS 影响很小 |
| 启动耗时 | splash 窗口约 1.0–1.5 s；主界面可交互约 4.2–6.3 s（受机器负载影响波动） |

## 6. 可调项清单（免改源码）

| 入口 | 可调内容 |
|---|---|
| `conf/launcher.vmoptions` | JVM 参数：`-Xms/-Xmx`、`-XX:MaxMetaspaceSize`、`-Dprism.lcdtext=false`（关 LCD 次像素渲染，中文更干净）、`-Dprism.order=sw`（软件渲染排障）、`-Dglass.win.uiScale` 等。⚠️ 写入不支持参数会导致**静默启动失败**（gui 模式无控制台） |
| `conf/conf.json` | 界面：主题/语言/字体/托盘；阅读器：主题、字号、字体、行距、页宽、对齐、翻页动画、窗口尺寸、背景图；下载：目录/线程/任务数/重试/格式；备份、代理、热键 |
| `conf/reader-theme.css` | 阅读器**自定义主题 CSS**（官方机制：主题选 `custom` 时加载），可定制背景色/文字色/字体平滑 |
| `conf/core.db` | SQLite：书架、书源、规则；可备份/替换/用 SQL 维护 |
| `fonts/` | 放入 TTF/OTF 字体自动加载（**路径需为 ASCII**，否则 JavaFX 11 加载失败） |
| `conf/app.json` | 启动器配置：更新地址 `url`、版本、变更日志、资源列表。改 `url` 可让更新检查快速失败或指向自建镜像 |

## 7. 本项目采纳/未采纳的优化项

| 优化项 | 采纳 | 理由 |
|---|---|---|
| 消除每次启动的更新日志弹窗 | ✅ | 反编译 `app.jar` 的 `App.start`，NOP 掉 `UpdateUtils.checkForUpdate(stage)` 调用（等长 4 字节替换），实测弹窗消失（UIA 元素 83→71） |
| 更新检查本地快速失败 | ✅ | `conf/app.json` 的 `url` 改为 `http://127.0.0.1:1/`，避免等待失效域名解析 |
| JVM 参数调优 | ✅ | 限制堆/元空间/代码缓存，`-Dprism.lcdtext=false` 改善中文渲染；实测参数生效 |
| 字体加载错误修复 | ✅ | 根因是安装路径含中文；改为安装到 ASCII 路径 `%LOCALAPPDATA%\Programs\UncleNovel` |
| 体积裁剪 | ✅ | 删除 Mac/Linux 的 kindlegen（约 50 MB），安装体积 196.1 MB → 146.6 MB |
| 阅读/界面默认调优 | ✅ | 预置 `conf/conf.json`：微软雅黑、字号 20、行距 0.2、下载线程 2、重试 1 |
| 免管理员安装 + 快捷方式 | ✅ | 安装到用户目录，快捷方式固定起始位置 |
| AppCDS 启动加速 | ❌ 未采纳 | 需优雅退出生成归档、与 jar/JVM 绑定，实测成本高、收益不确定，且启动瓶颈不在类加载 |
| 全局换肤（改 jar 内 CSS） | ❌ 未采纳 | 风险中（选择器耦合、易白屏），收益有限；阅读主题可走官方 `reader-theme.css` |
| TTS 源替换 | ❌ 未采纳 | 内置百度/思必驰接口可能失效，替换需要自备 TTS 接口并改 jar 资源，交给用户按需处理 |
| 绕过启动器直启 App | ❌ 未采纳 | 需自建模块启动命令，升级维护成本高；本版已通过补丁解决弹窗问题 |
