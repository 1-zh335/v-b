## 5. “跟上当前版本”的具体依据

- `cache-components`：SKILL.md 明确要求 **Next.js 16.3+**；本机 npm `next@latest` = **16.4.6**，满足。
- `update-docs`：基于 Next.js **canary** 工作流（`git diff canary...HEAD`、docs/01-app…）；安装快照取自 canary 当前分支。
- `fix`：来自 React 当前默认分支；内容是 React 仓库的 `yarn prettier`/`yarn linc` 脚本，版本本身不旧，但依赖该仓库脚本。
- `frontend-code-review`：Dify 上游已移除；本机为 marketplace 镜像旧版，**无法跟上 Dify 当前规范**。
- `find-skills`：CLI 主版本 1.9.0 为当前；但本机 `npx skills list -g` 只识别 Trae CN，说明它对 DSH 的 agent 目录未适配。
- 其余技能未发现硬编码旧版本 API；`frontend-design`/`fullstack-developer` 属通用指导。

## 6. 建议处理（按优先级）

1. **webapp-testing**：`pip install playwright` + `playwright install chromium`（或改用本机 Edge：`p.chromium.launch(channel="msedge")`）；把 `/tmp/inspect.png` 改为项目内相对路径或 `tempfile`。
2. **code-reviewer / pr-creator**：安装 GitHub CLI（`winget install --id GitHub.cli`）后再用远程 PR 流程；未安装时只用本地 review/模板整理。
3. **fix**：安装 `yarn`，或把命令适配到项目的包管理器；该技能仅适合 React 仓库脚本。
4. **frontend-code-review**：从活跃的 Dify 规范源重新获取或标记为 legacy；如继续使用，需补 `how-to-write-component`。
5. **find-skills**：不要直接用它把技能装到 `~\.trae-cn\skills`；DSH 的手工安装路径是 `$DSH_HOME\skills`（本次 10 个技能就是手工安装的）。
6. **cache-components**：如需其推荐工作流，手动安装 `next-dev-loop` 伴生技能到 DSH 目录；Windows 下把 `find` 命令换成 `Get-ChildItem -Recurse -Filter`。
7. **平台适配**：`webapp-testing` 的 `/tmp` 与 `cache-components` 的 Unix `find` 是明确的 Windows 不兼容点；其余技能无此问题。
