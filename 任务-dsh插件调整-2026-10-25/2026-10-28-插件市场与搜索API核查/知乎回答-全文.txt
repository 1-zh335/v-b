Search 和 Fetch 都是 5 元一千次，摊到每次是 0.005 元，我手头项目在用的博查，目录价是 0.036 元一次；Tavily 按量付费是 0.008 美元一次，换成人民币大概是五十多块一千次，这么一比，DeepSeek 的价格只有同行的零头，“价格屠夫又来了”。
￼
Search 接口每条结果还都会返回两个分数：
• 
rerank_score：0 到 3 分，综合相关性、权威性、时效性，文档写明大于等于 1.5 算优质结果；
• 
authority：0 到 4 的整数，-1 表示未知，文档写明大于等于 3 算“极权威结果”。
传统搜索引擎内部当然有站点质量分、页面质量分，但这类分数一直是黑盒，比如百度搜索是不会告诉查询用户某个页面权威性是几分的，Google 也不会，SEO 行业基本要么靠猜，要么靠排名变化反推。
DeepSeek 相当于在 API 响应里，写明了这个分数判断，然后交给调用方自己用，开发者在 Agent 里加一行 if authority >= 3 就能进行过滤，不用再去维护一份“可信站点白名单”。
以前搜索引擎的权力全部体现在排序上，搜索结果排到第几位，用户看到的就是第几，如果是人来操作，是可以往下翻的，也会自己来判断，如果不对还会换个关键词再搜，而现在调用方都是 agent 程序，程序不会“觉得哪里不对”，如果大量 Agent 都按 authority 阈值来决定读哪些、丢哪些，那么这个整数决定的就不只是排名，而是一个网页有没有资格进入模型的上下文。
￼
公告里还有一个说明：针对 SEO 作弊、GEO 操纵和低质 AIGC，通过严格的识别机制进行过滤。
GEO 这两年在国内火得有点离谱，我身边就有做内容营销的朋友转行接 GEO 的单子，业务就是批量生产“看起来像测评”的文章，铺到各个平台，好让大模型回答“某某品类哪家好”的时候带上客户的品牌，这类内容我自己在用各家 AI 搜索的时候碰到过不少，尤其是消费类问题，答案里引用的来源点进去一看，是同一个模板改出来的十几篇稿子。
所以 DeepSeek 把反 GEO 写进公告，再配上一个公开的 authority 分数，意思就很明显了，未来要承担的是AI 应用的信任层。
这里有一个很现实的循环。DeepSeek 自己的网页端和 API 每天处理数亿次搜索请求，这个量级意味着它能比小厂更早看到哪些内容在被批量投放、哪些站点突然冒出大量相似页面，识别 GEO 本质上是一个数据规模问题，看得越多，越容易认出模式，这是小的搜索 API 厂商比较难追上的地方，比价格更难追。
￼
公告还写到：用户在 DeepSeek Harness、Claude Code、Codex 里使用 DeepSeek API 时，已经通过 Server 端工具调用在访问 Search/Fetch 接口，目前不计费，11 月 1 日起开始按次收费。
说明，这个搜索能力早就在线上跑了，而且还是能跑在别家的编程工具里，开发者在 Claude Code 里把后端模型切成 DeepSeek，联网查文档的那一下，走的就是 DeepSeek 自己的搜索，工具虽然还是别人的，但数据流已经是 DeepSeek 的。
编程 Agent 对搜索的依赖比聊天场景强很多，写代码时查一个库的最新版本、某个 API 的参数变更、某个报错的 issue，这些都是强时效、强准确性的需求，搜错一次，后面几十轮工具调用基本全都白干，我自己用 Agent 写东西时最烦的就是它读了一篇过时的博客，然后信誓旦旦地用一个已经废弃的接口。从这个角度看，搜索质量对编程 Agent 来说是刚需，DeepSeek 先在这个场景里把搜索跑通，路径选得很准。
￼
还有几个细节，需要提一下：
• 
QPS 限制每个账号 5，Search 和 Fetch 分开来算，这个上限对大型企业来说明显不够用，说明当前阶段的目标用户是个人开发者和小团队的 Agent 项目，而不是要替代谁的企业级搜索采购。
• 
只对返回 200 且结果非空的请求计费，搜不到、超时、失败都不收钱。这个计费规则对开发者就很友好，调试阶段大量空查询也不会白花钱。
• 
summary 字段默认 600 到 800 字符，文档原话是"适用于给模型阅读"；snippet 是 100 到 200 字符，"适用于前端展现"。两套摘要分开给，可以看出设计时就默认就是给模型使用。
• 
支持 site:、lang:、after:、before: 这些语法，还有一个 ori_question 字段可以传入用户的原始问题来辅助理解意图。这个字段设计的很巧妙，搜索词和原始问题分开传，防止 Agent 改写出来的 query 丢失用户本意。
• 
Fetch 直接返回 Markdown，省掉了一层 HTML 清洗，这个做过 RAG 的都知道这一步有多烦。
￼
不过这里，我还是有一些疑问：
比如authority 这个分数怎么算出来的，文档里没写。我理解这是核心能力，不可能公开算法，但问题在于，一旦大量开发者把它当作默认过滤条件，一个没有公开标准的分数就会实际决定海量 AI 应用读到的信息范围。
举个具体场景：一个独立开发者写的高质量技术博客，没有大站背书，authority 可能只有 1 或 2。如果下游 Agent 统一设置 >= 3 的门槛，这篇博客在 AI 的世界里就等于不存在。传统搜索里，它好歹还能排在第二页被人翻到；在阈值过滤的逻辑下，它这个连第二页都没有。
我不认为 DeepSeek 有意这么做，但这个结构性风险是存在的，权威性判断天然偏向大站、老站、机构站，而很多真正一线的技术经验恰恰在个人博客、论坛帖子、GitHub issue 里。希望后续能看到更细的说明，比如分数的维度构成、申诉或者反馈机制。
