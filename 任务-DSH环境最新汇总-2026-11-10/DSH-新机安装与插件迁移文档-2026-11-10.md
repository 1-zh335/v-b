- 本文**不含**任何 token、授权码、密码、账号凭证值。源机 GitHub token 只存于 Windows 凭据管理器；夸克网盘授权码为一次性使用、未写入文档/仓库。**精确说明**：授权码本身未落盘，但夸克 Skill 目录 `deepseek\config.json` 会保留授权**状态**字段 `agent_auth`（含 userId/login_time 等，不含授权码）——迁移时不要拷贝该目录，新机重新登录授权。

### 1.2 两个 DSH profile（✅ 实测文件结构，2026-10-31）

源机同时存在两个 profile。**这是迁移时最容易忽略的一点**：

| profile | 谁在用 | 目录 | 当前 bundles 数 |
|---|---|---|---|
| `desktop` | DSH 桌面 App（GUI） | `%USERPROFILE%\.dsh\profiles\desktop\` | 18 |
| `web` | `dsh web`（Web UI）；源机 `dsh-start.bat` 固定端口 3080 | `%USERPROFILE%\.dsh\profiles\web\` | 4 |

每个 profile 目录的标准文件：

```
~/.dsh/profiles/<profile>/
├── package.json          # dependencies（后装插件）+ dsh.profile.bundles（启用顺序）
├── cordis.patch.yml      # 用户配置覆盖层（权限预设/模型/插件市场/子代理模型…）
├── cordis.yml            # 空入口列表，勿手改（组合由 bundles + patch 决定）
├── pnpm-lock.yaml        # 依赖锁定
└── pnpm-workspace.yaml
```

### 5.1 通用机制与验证方法

```powershell
# 查看 dsh plugin 的真实行为（源机实测输出：把参数转发给 profile 目录的 pnpm）
```

> 源机实测补充：`dsh plugin` **没有内置 `list` 子命令**——`dsh plugin list` 会报 `error: required option '--profile <name>' not specified`（exit 1）；正确用法是把 pnpm 参数一起转发：`dsh plugin --profile desktop list --depth=0`（exit 0；源机 desktop 显示 4 个依赖、web 显示 2 个）。第 2 版升级 subagent 到 rc.5 后，该命令**不再打印兼容性警告**（此前 rc.3 时会打印）。宿主加载态更直接的证据来自 `plugin_manager`：第 2 版实测源机 desktop 共 **226 条加载项**（升级 subagent 后 222→226），`list_bundles` **total 22 / enabled 18**（与 desktop bundles 一一对应；未启用的 4 个是官方模板 acp-app/headless/sdk-app/sdk-minimal，非本机添加）。

**源机实测的机制与坑**：

- `dsh plugin` 实际用**桌面端自带 pnpm**（24.21.0 运行时里的 pnpm 11.28.5），其内置 **24 小时 `minimumReleaseAge`**：刚发布的新版本会被暂缓或报 `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`。源机 2026-10-25 装 cost-meter 时最新 1.9.36 被暂缓，自动解析到 1.9.31（📄 记录）。需要立即装可加 `--config.minimum-release-age=0`（⚠️ 源机未实测该参数效果）。
- 安装后的**生效判据**（不要只看命令 exit 0）：
  1. `~/.dsh/profiles/<profile>/node_modules/<包名>/package.json` 里版本正确；
  2. profile 的 `package.json` 的 `dependencies` 与 `dsh.profile.bundles` 都包含该包；
  3. 运行中宿主 `plugin_manager` 清单出现对应条目且 `fiberPhase: active`（源机用 DSH 的 plugin_manager 工具查，第 2 版 desktop 总条目 **226**）；

#### 12.6.6 完美移植步骤（按顺序）

1. **新机基础**：装 DSH 桌面端（§3）→ 登录 DeepSeek 账号 → 确认 `%USERPROFILE%\.dsh\profiles\desktop\` 已生成。
2. **规则与工具**：clone `https://github.com/1-zh335/v-b`（或拷贝工作区），把 `AGENTS.md` 放工作区根，`工具\浏览器` 里 `npm install`（§8）。
3. **desktop 配置**：备份新机 `package.json`/`cordis.patch.yml` → 按 §12.6.4 写 `cordis.patch.yml` → `dsh --profile desktop --dump-config` 验证无报错。
4. **插件**：`dsh plugin --profile desktop add dsh-cost-meter@1.9.62 --save-exact`；需要 subagent 时按目标机内核装匹配版本（源机 rc.5）；桌宠装好后按 §5.3 加入 `@dsh-pet/bridge`（link 路径按新机替换）；用 `plugin_manager` 核对 active（§9.2 #10/#21）。
5. **桌宠**：装 v4.4.0（对安装包 SHA-256）→ 设置里重新填 DeepSeek Key、小米 MiMo Key（如需 TTS）→ 退出桌宠，把 §12.6.5 的 `config.json` 备份替换（保留新机的 Key 引用或重新设置）→ 重启桌宠，按 §6.5.1 验证。
6. **夸克 Skill**：按 §7 安装并从官方页面重新 `login --token`（授权码一次性）。
7. **web profile（可选）**：按 §12.6.3 写 `package.json`，`dsh plugin --profile web add dsh-cost-meter@1.9.62 --save-exact` + `@dsh-pet/bridge`，`dsh --profile web --dump-config` 验证。
8. **GitHub/凭据（可选）**：按 §8.5 配 remote 与 token；**所有 token/Key/授权码在新机重新生成/填写**。
9. **验收**：按 §9 全部清单 + §12.4 待验证项逐条确认；把结果回填到 §12.5 变更记录。

#### 12.6.7 不要带的（摘要，详见 §8.6）

- `~/.dsh/.credentials.yaml`、`sessions/`、`attachments/`、`cache/`、`profiles/node_modules/`（含根级遗留与各 profile 内 node_modules）、Edge 自动化 profile、Skill 的 `deepseek\config.json` 授权缓存、各类 token/授权码文件。
- 不要在未核对内核版本时整目录复制 profile（subagent rc.3 案例，§4.2）。
